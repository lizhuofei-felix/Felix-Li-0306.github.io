# LI Zhuofei | Professional Profile

Professional personal profile for LI Zhuofei, published with GitHub Pages at [lizhuofei.com](https://lizhuofei.com/).

## Overview

This repository contains a single-page personal profile built with plain HTML, inline CSS, and a small inline JavaScript enhancement. There is no framework, package manager, build step, or JavaScript dependency. The page presents LI Zhuofei's Statistics and Computer Science background, research interests, project contributions, internship experience, and campus service. All content and links remain usable with JavaScript disabled.

The redesign approved in September 2026 uses the reading structure of [Brittany Chiang's site](https://brittanychiang.com/): a persistent identity column beside a continuous body of content. Its slate backgrounds, restrained typography, and factual copy retain the character of a personal document. This approved direction replaces the former 780px single-column sheet, topbar, and emerald palette.

The owner subsequently requested matching the reference site's interactions, including visible entry elevation and contact icons. The latest direction calls for a stronger pointer glow and colors closer to the reference: slate backgrounds, teal accents, and a blue glow behind the content. This supersedes the intermediate steel-blue accent and faint-glow settings, as well as the former blanket bans on JavaScript, gradients, and hover movement within the approved interaction scope.

## Design Style — read before changing the UI

This page should read as a **carefully typeset personal document**. Formality comes from precise copy, consistent alignment, readable text, and sufficient space.

**Layout**

- Maximum page width of 1120px. On wide desktop screens, a 320px identity column and a 96px gap leave the remaining width for the main content. Between 961px and 1100px, use a 290px identity column and a 64px gap.
- The identity header (`#profile.identity`) stays visible with `position: sticky` and a 72px top offset. Desktop viewports 641–760px high use a compact sidebar with a 32px top offset and a 32px page top margin; at 640px high and below, disable sticky positioning so every contact link remains reachable. Navigation links point into the main content; the four contact/CV icons live in the identity column's `#contact` block.
- One continuous `<main id="content" class="content">`, with simple hairline section dividers. Entries have no permanent card frames or outer paper border; subtle panels and shadows appear only on desktop hover or keyboard focus.
- At 960px and below, switch to a single column and place the identity header in normal document flow. At 600px and below, stack entry titles and dates, and collapse skill labels and values into one column. Navigation can wrap; avoid horizontal overflow at narrow widths.
- Keep a single page scrollbar. Do not create an independently scrolling content pane.

**Typography**

- Serif (`EB Garamond`) is reserved **only** for the name (`h1`), set in mixed case (`LI Zhuofei`) with slight positive letter spacing. All other text uses `Inter`.
- Introductory body copy is approximately 16px, with entry descriptions at 14px and generous line height. Dates use 13px. Titles, roles, dates, and descriptions have consistent visual hierarchy.
- Skills use compact categorized text. Keep technology descriptions concise and avoid decorative pill collections.
- No numbered section kickers ("01 / 02 / 03...") or per-entry icon badges.

**Color**

- Use CSS custom properties for both palettes, with the dark palette in `@media (prefers-color-scheme: dark)`. Update both whenever changing a color token.
- Use a teal accent for ordinary-link hover, project hover, results, and keyboard focus outlines. Ordinary links default to the main text color; headings, active/hovered navigation, and hovered social icons use the main text color. The approved blue radial glow is a background effect, not an additional content accent. Other decorative gradients and warm cream/ivory backgrounds remain outside the design.
- Keep the glow behind the content (`.spotlight` at `z-index: 0`, positioned `.layout` at `z-index: 1`) so it does not tint glyphs. Preserve readable body text when sibling entries dim or a hover panel appears.

**Interaction**

- Use native anchor navigation and ordinary page scrolling. CSS provides smooth scrolling when reduced motion is not requested; do not intercept anchor clicks or replace the browser's fragment/history behavior.
- A small inline script marks the current section with `aria-current="location"`, using a stable reading line and a final-section fallback at the document bottom. Scroll work is batched with `requestAnimationFrame`; manual scrolling does not rewrite the URL.
- Desktop navigation rails expand from 32px to 64px for hover, keyboard focus, and the current section. On mobile, the current item uses an underline. Navigation and link transitions are approximately 150ms.
- Fine-pointer desktop hover and keyboard focus raise an inner `.entry-surface` by 3px over 220ms, with a subtle top edge and two-layer shadow. Keep the outer `.entry` and its transparent hover buffer stationary so the expanded boundary does not move. The buffer sits behind the surface without intercepting its project link. Sibling entries dim to 0.9 opacity to retain text readability. Project source links extend across their surfaces and retain a visible focus outline; their arrows move 4px up and right on hover/focus.
- The radial glow follows mouse movement only on fine-pointer desktop screens with reduced motion disabled. Its diameter is 800px with an explicit 400px radius. Light mode uses `#3B82F6` at 0.09 center opacity; dark mode uses `#1D4ED8` at 0.15. Each reaches half that opacity at 50% radius and transparency at 100%. Pointer position updates are frame-batched with a 140ms follow transition. The glow stays behind content, cannot intercept pointer events, is hidden from assistive technology, and disappears when the pointer leaves or the window loses focus.
- The contact row has four named 44×44px link targets, in order: GitHub, LinkedIn, Email, and CV. The first three use 24px inline SVGs; the fourth displays only `CV`, set at 17px/700 inside a 24px `.cv-mark` area. All four marks inherit the link color and are hidden from assistive technology. Keep the email address in its link label and `mailto:` destination. The CV link keeps its `cv.pdf` target and accessible PDF/new-tab label; do not add a separate View CV text row or CV arrow. All four marks rise 3px over 180ms on hover/focus when motion is allowed.
- Name and footer links use `#top` on the root HTML element to return to the document start. Keep `#profile` on the identity header for existing links, and `#content` as the keyboard skip-link target.
- Reduced-motion mode uses immediate anchor scrolling, no transition animation, no surface or icon lift, no moving arrows, and no pointer glow. Static panel depth, section highlighting, and visible keyboard focus remain functional.
- The entire document and all links must remain usable with JavaScript disabled. Do not add scroll-reveal gating, parallax, independent scrolling panes, or decorative per-entry icon badges.

Interaction verification includes manual scrolling in both directions, all navigation targets, the short final section, direct fragment loads, browser back/forward, responsive and height breakpoints, reduced motion, keyboard use, and JavaScript-disabled fallback. Check that entry edges do not cause hover flicker, expanded project links still cover the whole surface, and contact icons retain their labels and 44px targets. Record actual results in `design-qa.md`; these requirements do not imply they have already passed.

**Content**

- The supplied CV and LinkedIn profile are the content sources. The owner specified that LinkedIn dates take precedence where the sources differ; keep the public CV consistent with the approved website dates.
- Copy must reflect the actual scope of each role. Preserve "Participated in" and "Attended" where those describe the contribution. Do not strengthen roles, ownership, or outcomes without confirmation from the owner.
- Entry titles identify the organization, institution, or project; subtitles hold the role, degree, or location; dates use a separate `.entry-meta` line.
- Dates use month-level precision, with an en dash for ranges. Distinguish course grades from project scores, and research interests from completed research experience.
- The subdued footer `Last updated` line records the actual website update date as static text. When content or interface changes, update both its `<time datetime="YYYY-MM-DD">` value and visible date together; never substitute the visitor's current date or `document.lastModified`.
- Page copy uses HTML entities such as `&ndash;` and contains no em dashes.
- The bio line under the name (`.role`) and the `<meta name="description">` / `og:description` should stay in sync with each other.
- Keep `LI Zhuofei` as the main name, with the preferred name `Felix` on a separate sans-serif line below it. The visible identity line is `Statistics Undergraduate at HKU`. The page title and `og:title` are `LI Zhuofei (Felix) | Statistics Undergraduate at HKU`, preserving the owner's preferred name and explicit undergraduate status.
- Publish only the private CV repository's `variants/public/pdf/LI_ZHUOFEI_Resume_Public_2026.pdf` as `cv.pdf`. Never copy the phone-bearing attachment, Standard, or Print variant directly into this repository.
